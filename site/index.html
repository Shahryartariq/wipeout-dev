Delete the folder Windows won't let you delete.

Windows only says the folder is open in another program. Wipeout tells you which one, stops it, and wipes the folder, even a node_modules with 100,000 files.

Download for Windows Source on GitHub

Free and open source (MIT). Windows 10 and 11. No account, no tracking.

It finds what other tools miss

A folder can be held in four ways. Explorer can't tell you about any of them. Most unlocker tools catch the first.

  • A program has a file open

    A dev server, a file watcher, your editor. Wipeout reads every open handle on the system and names the program the way you'd describe it: "Vite dev server on localhost:5173", "npm start".

  • A terminal is sitting in it

    You cd'd into the folder in Git Bash last week and never closed the window. That's enough to block the delete.

  • A library is loaded from it

    Native add-ons (.node files) and DLLs inside node_modules are loaded into memory and never show up as open files. Wipeout checks every process's loaded libraries too.

  • A program runs from inside it

    An electron.exe or esbuild.exe started from node_modules locks the folder it lives in.

One click on Stop ends the whole chain (terminal, npm, node) but never closes VS Code, Explorer or your browser.

No "Are you sure?" to click through on autopilot

Deleting takes a press and hold, so it's always on purpose. Then it's fast: Wipeout deletes in parallel with a live count, clears read-only files as it goes, and handles paths over Windows' 260-character limit.

Try it: press and hold the bar (or focus it and hold Space).

Clean every old node_modules at once

Point Wipeout at your projects folder. It lists every node_modules (and Rust target) with its size and when you last touched the project, and ticks the ones idle for 30 days or more. If something is holding one, it says what, and stops it before wiping.

Your code stays. Run npm install in a project to get its dependencies back.

Built so it can't wipe the wrong thing

  • Refuses dangerous folders. Whole drives, Windows, Program Files, your user folder and anything that contains them.
  • Never follows links. Drop a junction or symlink and only the link is removed. The folder it points to is untouched.
  • Never stops Windows. Explorer, Windows Security and system processes get advice instead of a Stop button.
  • Checks before it stops. If a process ID now belongs to a different program, Wipeout leaves it alone.
  • Warns about unsaved work. Git repos show uncommitted changes, unpushed commits, or "this repo exists only here".
  • Works offline. No account and no telemetry. The only network call is the update check against GitHub.

Questions

How do I delete a folder that's open in another program?

Drop the folder into Wipeout. It lists every program holding the folder, in plain words, such as "React dev server on localhost:3000, started from a PowerShell window". Click Stop, then hold the wipe button. Wipeout stops that program and the processes it started, and deletes the folder.

How do I fix EBUSY: resource busy or locked when deleting node_modules?

EBUSY means a running process still has a file inside node_modules open. It's usually a dev server, a file watcher, VS Code, or a terminal sitting in the folder. Wipeout finds it, including native add-ons loaded as libraries, which other tools miss, and stops it before deleting. The same goes for EPERM: operation not permitted, unlink.

"Source Path Too Long": how do I delete a folder with a path that's too long?

File Explorer can't delete paths over 260 characters, and deep node_modules folders often have them. Wipeout deletes them without you turning on the LongPathsEnabled setting or renaming anything.

How is it different from PowerToys File Locksmith or IObit Unlocker?

Those show you node.exe. Wipeout tells you it's a Vite dev server on port 5173 started from Git Bash. It stops that whole chain without closing your editor, catches libraries loaded from the folder, deletes node_modules in parallel past the 260-character limit, and can clean every old node_modules under a folder at once. It's free, open source, and has no bundled offers.

Is it safe?

It refuses drives, Windows, Program Files and your user folder, never follows links, never stops parts of Windows, and checks that a process is still the same program before stopping it. Deleting is permanent (it skips the Recycle Bin), so it asks you to press and hold. The code is on GitHub with tests for each of these rules.

Why doesn't the folder show what's holding it?

Programs running as administrator can hold files without being visible to a normal app. Use Restart as administrator in Wipeout. Locks inside some antivirus or backup drivers can't be traced to a program at all. Wait a few seconds and rescan.

Does it collect data?

No. Wipeout has no account, no analytics and no telemetry. It checks GitHub for updates and keeps a local log in %APPDATA%\Wipeout\logs that never leaves your PC.
